## Recording behavior and fallback

Start opens floating controls immediately, while activation is available, and shows the countdown there. Pause/resume/stop share the same hook handlers in both windows. Closing the floating window keeps recording going and exposes a Float controls button in Speak. Stopping, cancelling, and unmounting close the child. Alt+Shift+P toggles pause and Alt+Shift+S stops when Speak or its floating window has focus. These are intentionally not advertised as global OS shortcuts: a normal web page cannot receive keystrokes in another app. The browser's own Stop sharing button remains the universal fallback. A web page cannot minimize the user's other windows or choose where the OS places the Picture-in-Picture window.

Document Picture-in-Picture requires a gesture and exposes pagehide for lifecycle cleanup; see [Chrome's API documentation](https://developer.chrome.com/docs/web-platform/document-picture-in-picture). Public single-document access and collection listing are different operations; see [Firebase rule structure](https://firebase.google.com/docs/firestore/security/rules-structure).

## Robustness and scale limits that still matter

- **High for long sessions:** recording chunks, raw/remuxed blobs, ffmpeg's in-memory filesystem, segment outputs, and final output can coexist. 1080p and releasing captured chunks reduce pressure but do not make recording unlimited. Browser memory limits, sleep, crashes, and device resource contention can still lose a long session. Durable chunk storage/multipart workflows would require a separate persistence design.
- **High before broad public usage:** authenticated users can still request unlimited signed uploads. No durable per-user quota, rate limit, upload verification, or orphan cleanup job exists. MIME signing is not validation of the actual file. Successful B2 upload followed by failed Firestore write can orphan a public object; retry can create another object. Deleting metadata does not delete the B2 object. These require server/storage lifecycle policy, not a client-only patch.
- **Medium:** metadata is client-authored. Rules now enforce its shape and owner, but cannot prove a B2 object exists, matches the claimed duration, or belongs to the configured download host. HTTPS alone is not a host allowlist. Before opening the service broadly, finalize and verify uploads server-side and restrict the storage host there.
- **Medium:** reload closes the in-memory editor. A beforeunload prompt warns while setup, recording, or an unsaved recording is present, but browser/OS termination can bypass it. There is no autosave or recovery. Sign-out tears down resources; it does not preserve the edit.
- **Medium:** npm audit reports 11 dependency-tree advisories (3 high, 8 moderate). High findings are in @vercel/node's transitive path-to-regexp/undici toolchain; the app imports its types only. Moderate findings include firebase-admin's storage/request dependencies and UUID paths not directly used in this app. No exploitability assessment against the hosted runtime was possible. The offered forced fixes downgrade major SDK versions; these were not applied blindly. Update upstream packages with compatibility tests before treating the dependency tree as clean.
- **Medium:** the same-origin ffmpeg WASM asset is about 32.1 MB (about 10.3 MB gzip in the measured build). First edit still downloads/initializes it; export is CPU-intensive even in its worker. Slow devices will be slower, and UI serialization/copies still consume memory. Offline editing works only if required assets are already available to that session/cache; no offline-first guarantee is made.
- **Medium:** selected camera/mic denial or a missing device fails setup and releases acquired streams. The user can disable that option and retry. A cancelled screen picker returns an error. No silent substitution of another input is performed. Only WebM-compatible recording is supported; an unsupported MediaRecorder path returns an error. Camera unplugging, physical microphones, protected media, and system-audio support need real-device checks.
- **Low/medium at large clip counts:** timeline operations and playhead rendering are linear in clip count; trimming seeks on pointer movement and listeners rebind as callbacks change. Ordinary short recordings remain the target. Hundreds of clips and slow disks/devices have not been profiled. Preview boundaries use media events/frame sampling and are not guaranteed sample-accurate; ffmpeg defines exported cuts.
- Worker timers preserve the existing background-recording design. They cannot override OS sleep, a discarded tab, GPU/encoder overload, or every browser's throttling policy. Detached capture was verified; extended real background-tab recording on multiple browsers remains a manual test.

## Verification and deployment notes

Completed checks: production build passed; lint passed without warnings; 15 unit/integration regressions passed; the Edge browser test passed, including native Picture-in-Picture pause/resume, detached changing-frame capture, real remux/MP4, split invalidation, export cancellation, and successful export after cancellation. The editor screenshot was visually inspected. The remaining Vite size notice is for the lazily loaded Firebase chunk.

Final lifecycle review also added export ownership/unmount cancellation, an AbortSignal through signing and XHR upload, and cleanup for the copied-link timer. Late export completion cannot create an orphaned object URL after editor unmount. A Firestore write already submitted is not cancellable, which is part of the cloud transaction limitation below.

Run npm run build, npm run lint, npm test, and npm run test:browser (uses installed Edge). Automated tests use generated media or mocks and dummy credentials. They do not sign into Firebase or upload to B2. Browser tests mount App in an isolated test document; no authentication bypass was added to production.

Real sign-in, the native screen-share picker, webcam/mic audibility, an actual B2 upload/public playback, offline recovery, a long background recording, and live Vercel behavior were NOT verified. The Firestore rules file must be published separately using the existing Firebase setup; pushing to GitHub alone does not deploy rules. B2 must allow the application's origin, PUT, and Content-Type through CORS. Keep bucket application credentials server-only and retain the existing public-bucket intent for shared recordings.

The plain three-route routing is retained: /v/<id> is outside AuthGate, /app is gated, and root is public. Existing rewrites exclude api/ and were not changed. No local secrets are included in the commit.
